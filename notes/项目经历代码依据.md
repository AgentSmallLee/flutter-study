# 红松心选 Flutter 项目 - 简历内容代码依据

> 本文档对应简历中「红松心选 Flutter 客户端」项目的 7 条核心职责，逐条列出代码中的真实实现位置，方便复习和面试前快速定位。

## 1. Flutter 业务模块架构设计与落地

**简历描述：**
> 主导电商 Flutter 模块从 0 到 1 搭建，采用 Clean Architecture 三层分层（data/domain/presentation），基于 flutter_bloc + Equatable 实现状态驱动 UI，使用 get_it 完成全链路依赖注入；设计全局单例 Bloc（购物车/首页/认证/分类）与页面级工厂 Bloc（商品详情/订单/搜索）混合策略，既保证跨页面状态一致性（如购物车角标实时同步），又避免全局状态膨胀，目前已落地 8 个业务模块、代码量约 1.2 万行

**代码依据：**

| 要点 | 文件路径 | 关键代码 / 类 |
|------|---------|-------------|
| Clean Architecture 三层结构 | `lib/features/*/` | 每个 feature 下都有 `data/`、`domain/`、`presentation/` 三层目录 |
| 8 个业务模块 | `lib/features/` | auth / cart / category / home / order / product_detail / profile / search |
| 代码量统计 | - | Dart 代码约 11,769 行（`wc -l lib/**/*.dart`） |
| flutter_bloc + Equatable | `lib/features/*/presentation/bloc/` | 每个 Bloc 继承 `Bloc<Event, State>`，State 用 `Equatable` 实现值比较 |
| get_it 依赖注入 | `lib/core/di/service_locator.dart` | `configureDependencies()` 统一注册 Core → DataSource → Repository → UseCase → Bloc |
| 全局单例 Bloc | `service_locator.dart` `_registerBlocs()` | `registerLazySingleton<HomeBloc>()` / `CartBloc` / `AuthBloc` / `CategoryBloc` |
| 页面级工厂 Bloc | `service_locator.dart` `_registerBlocs()` | `registerFactory<ProductDetailBloc>()` / `OrderListBloc` / `OrderDetailBloc` / `SearchBloc` / `LoginBloc` |
| 跨页面状态一致性（购物车） | `lib/features/cart/presentation/bloc/cart_bloc.dart` | CartBloc 全局单例，任何页面通过 `getIt<CartBloc>()` 获取，状态自动同步 |

## 2. 混合开发方案设计与实现

**简历描述：**
> 设计多仓 + Flutter Module 集成方案，以 aar 产物形式供 Android/iOS 原生依赖，原生团队无需搭 Flutter 环境即可编译；封装 FlutterEngine 预加载与缓存策略（FlutterEngineCache），首页渲染完成后异步预热引擎，Flutter 页面打开耗时从 800ms+ 降至 100ms 内，实现秒开体验；设计 NativeBridge 单例管理器，基于 MethodChannel 统一封装登录态共享、微信支付、相机/相册、推送等 8+ 原生能力，业务层不直接接触 Channel，降低使用成本与出错概率

**代码依据：**

| 要点 | 文件路径 | 关键代码 / 类 |
|------|---------|-------------|
| Flutter Module 模式 | `pubspec.yaml` | `module:` 配置：`androidPackage: com.example.flutter_ecom` |
| aar 产物集成 | `android_ecom/FLUTTER_INTEGRATION.md` | 打 aar、maven 依赖、多环境配置说明 |
| FlutterEngine 预加载 | `android_ecom/app/.../bridge/FlutterBridgeManager.kt` | `preloadEngine()` + `FlutterEngineCache.getInstance()` + `ENGINE_ID = "ecom_engine"` |
| 预热时机说明 | `FlutterBridgeManager.kt` 注释 | "首页渲染完成后异步预热，平衡启动速度和 Flutter 页面打开速度" |
| 多引擎 vs 共享引擎对比 | `FlutterBridgeManager.kt` 注释 | 共享引擎：内存小、状态共享；多引擎：隔离好、内存大 |

## 3. 网络层封装与错误治理

**简历描述：**
> 基于 Dio 封装统一网络客户端，设计 Auth / Logging / Error 三层拦截器链，实现 Token 自动注入（Bearer 认证 + 401 全局登出）、请求响应日志统一输出、异常分类上报；结合 dartz 的 Either 与自定义 Failure 体系（ServerFailure / NetworkFailure / UnauthorizedFailure / BusinessFailure / CacheFailure），将 try-catch 异常转为函数式返回值，编译期强制调用方处理失败分支，减少线上未捕获异常

**代码依据：**

| 要点 | 文件路径 | 关键代码 / 类 |
|------|---------|-------------|
| Dio 统一封装 | `lib/core/network/dio_client.dart` | `DioClient` 类，封装 get/post/put/delete，统一 BaseOptions 配置 |
| 三层拦截器链 | `dio_client.dart` 构造函数 | `_dio.interceptors.addAll([authInterceptor, loggingInterceptor, errorInterceptor])` |
| 拦截器执行顺序说明 | `dio_client.dart` 注释 | 请求阶段按添加顺序，响应/错误阶段逆序，Auth 放最前 |
| Auth 拦截器（Bearer Token） | `lib/core/network/interceptors/auth_interceptor.dart` | `options.headers['Authorization'] = 'Bearer $token'` |
| 401 全局处理 | `auth_interceptor.dart` `onError` | 判断 `err.response?.statusCode == 401`，预留登出逻辑 |
| Logging 拦截器 | `lib/core/network/interceptors/logging_interceptor.dart` | 统一输出请求/响应日志 |
| Error 拦截器 | `lib/core/network/interceptors/error_interceptor.dart` | 统一错误日志记录 + 错误信息透传 |
| 6 种 Failure 类型 | `lib/core/error/failures.dart` | `Failure` 抽象基类 → ServerFailure / NetworkFailure / UnauthorizedFailure / BusinessFailure / CacheFailure / UnknownFailure |
| Result 类型别名 | `failures.dart` | `typedef Result<T> = Either<Failure, T>;` |
| 错误统一转换 | `lib/core/error/error_handler.dart` | `ErrorHandler.handleDioError()` 将 DioException 转为对应 Failure |
| Repository 中使用 Either | `lib/features/auth/data/repositories/auth_repository_impl.dart` | `try { return Right(...) } catch(e) { return Left(ErrorHandler.handleError(e)) }` |

## 5. 本地存储方案选型与实现

**简历描述：**
> 针对不同数据特性选型存储方案——购物车结构化数据使用 Hive NoSQL 存储，自定义 TypeAdapter 实现类型安全的对象序列化，以 productId 为 key 保证单条记录唯一性，读写性能优于 SQLite；用户 Token、搜索历史等轻量 KV 数据使用 SharedPreferences；两种方案各取所长，满足性能与开发效率的平衡

**代码依据：**

| 要点 | 文件路径 | 关键代码 / 类 |
|------|---------|-------------|
| Hive 购物车存储 | `lib/features/cart/data/datasources/cart_local_datasource.dart` | `CartLocalDataSource`，注入 `Box<CartItemHiveModel>` |
| productId 为 key | `cart_local_datasource.dart` | `_box.put(item.productId, item)` — 同一商品只有一条记录 |
| 自定义 TypeAdapter | `lib/features/cart/data/models/cart_item_hive_model.g.dart` | `CartItemHiveModelAdapter extends TypeAdapter<CartItemHiveModel>` |
| Hive 初始化 & 注册 Adapter | `service_locator.dart` `_registerCore()` | `Hive.registerAdapter(CartItemHiveModelAdapter())` + `Hive.openBox<CartItemHiveModel>('cart_box')` |
| SharedPreferences 存 Token | `lib/features/auth/data/datasources/auth_local_datasource.dart` | 保存/读取 userToken、userInfo |
| SharedPreferences 存搜索历史 | `lib/features/search/data/repositories/search_repository_impl.dart` | 搜索历史的本地持久化 |
| 选型理由说明 | `cart_local_datasource.dart` 注释 | 4 点：对象存储不用序列化 JSON / 性能好纯 Dart / 增删改查方便 / TypeAdapter 类型安全 |
